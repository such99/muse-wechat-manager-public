# r11 审查候选：收发恢复修复

本候选基于已发布 r10 提交 `fde05de`，用于独立复核。已发布的 r10 ZIP、标签和资产哈希保持原样；当前修复没有安装到正在使用的连接，也尚未作为新的便携 Release 发布。

## 对审查报告的处理

| 项目 | 核验与处理 |
| --- | --- |
| 1：Muse inputs 锁无解除入口 | 已确认并修复。Muse 新增本地及 Bearer 认证的人工核对接口。桥接先核对当前绑定者对应的 Muse source ID，成功后才清桥接对应记录；响应丢失时可重复同一核对。解除结果不清除去重，也不重发原输入。 |
| 2：未提交输入重启后无提示、重投被丢 | 已确认并修复静默与去重路径。明确未提交的 restart/shutdown 记录允许同 ID 重投重新入队；在原发送者下一条入站消息时，提示未提交文字/附件数量。纯文字和媒体负载仍只保存在内存，不承诺恢复原内容，需本人核对并重发。已确认、未知结果、人工取消项均不重新入队。 |
| 3：claim 响应丢失被当 uncertain | 保留保守策略。未新增“发送开始”协议或宣称已修复。仅凭本地 claim 结果不能保证远端没有发生其他操作，发送结果不明仍需人工核对。 |
| 4：generation_halted 无正常解除 | 已确认并修复。只对主聊天、已就绪且已消费的失败记录暂停。暂停记录持久化，人工核对精确 seq/message ID、账号及页面空闲后才能继续；后续正常记录不会擅自解除，也不重生成。真实网页手动停止会返回何种事件仍未真机验证。 |
| 5：iLink -2 的重发语义 | 未证实、未改策略。当前仍将结构化 -2 视为拒收并等待新会话再试；图片上传与 sendmessage 是不同步骤，但缺乏真实平台关于送达的充分证据。媒体重复风险仍列为待验证，不能据此承诺绝对“至多一次”。 |
| 6：去重容量与共享 stop | 未修改。容量达到 10,000 条/24h 时停止粒度较大，仍是已知限制；本候选不宣称所有报告项已关闭。 |

## 恢复操作的边界

- 必须确认当前账号、确切输入或失败记录，并等待页面空闲、没有网页草稿、记录已稳定；新失败出现后旧确认失效。
- `not_submitted_reviewed` 是不可重试的终态，保留原输入 ID。人工核对取消旧项不等于把旧项重新入队；需要发送新的微信消息。
- 原请求仍等待 ACK 时，“确认未提交”不能撤销在途请求，因此拒绝解除。只有本人已确认该输入出现在 Muse，才能以 acknowledged 解除其等待；晚到的旧 ACK 不得解除新请求的锁。
- 历史数据库没有 request ID 时仍保留去重状态；发现当前页面有不匹配的活动请求会拒绝解除。
- Muse 与桥接不共享一个数据库事务。Muse 先执行幂等核对，桥接仍暂停时可再次明确核对同一项；不把网络失败视为两侧均成功。

## 其他已处理项

`/local/` 写请求在接收过程中限制为 64 KiB，不依赖 Content-Length，覆盖分块传输；不将该限制冒充媒体上传接口的大小保护。非 ASCII Cookie/Bearer 比较改为安全字节比较，认证失败不再因 compare_digest 类型限制报 500。

新建实例和示例配置默认关闭正文日志；既有配置不自动改写。普通助手发送队列仍会把正文存入本机 SQLite，诊断日志保留到手动删除。DPAPI 加密的是凭据，不是所有聊天数据，也不是对同 Windows 用户恶意进程的隔离。

保留上游 vendor 固定字节与锁文件，新增实际 StrictEngine 启动参数测试，阻止使用 `--no-sandbox` 或通配 CDP origin 回归。没有增加本机进程之间的权限隔离，不能将 Host/Origin、nonce 或点击确认描述成这种保证。
