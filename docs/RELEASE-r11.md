# 0.1.0-preview-r11 发布说明

发布日期：2026-10-16（北京时间）。本次把已审查的队列恢复改进和 Muse 登录确认修复汇总为一个 Windows x64 便携版本。

## 包含的更新

- 修复登录 Muse 后确认主聊天仍报 HTTP 409：接受 `__Host-hatch_one_tap` 等带连字符的 Cookie，恢复时保留 `__Host-` 的主机作用域。六组和后续新增实例共用同一修复。
- 对未确认的 Muse 输入、微信队列和生成暂停提供需本人核对的恢复入口；保留去重，未知结果不会自动重发或重新生成。
- 明确未提交的重启/关闭记录可重新入队，并在原发送者下一条消息时提示需要重发的文字或附件数量。
- 新实例默认关闭正文日志；保留请求大小限制和跨站保护。管理器显示完整版本号 `0.1.0-preview-r11`。
- 继承 r10 的任务状态卡过滤、网页/提醒文字提示及取消应用内累计发送门槛。

## 下载与验证

从 [r11 Release](https://github.com/such99/muse-wechat-manager-public/releases/tag/v0.1.0-preview-r11) 下载 ZIP，按同页 `SHA256SUMS.txt` 核对后完整解压，双击 `Muse微信管理台.exe`。需要 Windows x64、Google Chrome 和 .NET Framework 4.x；包内自带 Python 与运行依赖。

Release 同时提供 `manifest.json` 和 `bundle-verification.json`。前者列出包内文件哈希，后者记录新解压副本的 EXE 启动、重启、退出、自动恢复工作进程、端口保护、版本号及随包依赖检查。134 项假数据/本机回归已通过，具体范围见 [测试报告](../packaging/TEST-REPORT.md)。

本机修订安装的实例 2 已由使用者确认微信绑定和测试通过，见 [登录修复与验收记录](LOGIN-409-FIX-2026-10-16.md)。这不代表下载包已完成所有真实账号、媒体和平台恢复场景的验收。

## 已经在用旧目录怎么办

若既有安装已逐项应用本次修复并且运行正常，可以继续从原入口使用，无需为了目录名或版本显示重新登录、迁移或重装。发布过程中不会修改正在使用的连接。本次本机核对的旧命名目录已包含全部 25 个运行文件的功能修复；新版另更新版本显示及文档。

未应用修复的其他安装，可在没有进行中对话时退出管理器，确认其启动的实例已停止，再备份整个原安装到本机私人位置。先将新版解压到另一个目录，核验哈希，然后只替换原目录中的程序文件和随包运行库；必须保留原 `instances/`、`secrets/`、`runtime/` 与 `manager-data/`，不要用新版六份空配置覆盖。继续从原目录启动，凭据仍按原 Windows 用户和原实例作用域恢复。不要同时运行两份使用相同配置的安装。

发布包中的六份实例配置均未登录、关闭自动启动；不包含使用者的凭据、绑定、聊天、队列或浏览器会话。切换 Windows 用户或机器时需重新认证，不能把复制 DPAPI 文件当作迁移授权。

## 仍保留的限制

网页/提醒目前使用文字提示，截图转发和语音支持尚未实现。真实六账号并行、MiMo、授权过期恢复和 iLink `-2` 的送达语义仍待相应实测。去重容量达到上限时暂停粒度较大；未知发送结果仍需本人核对。详见 [审查说明](CLAUDE-REVIEW-FIXES.md) 与 [验收矩阵](../packaging/ACCEPTANCE.md)。

r10 标签、ZIP 和校验值保留原内容；本次使用独立 r11 标签和新资产。
