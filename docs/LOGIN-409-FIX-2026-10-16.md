# Muse 登录确认 HTTP 409 修复与实例 2 验收

记录日期：2026-10-16（北京时间）。本记录只包含问题、修复和验收范围，不包含账号、认证值或聊天内容。

## 问题与原因

实例 2 在专用窗口登录 Muse 后，点击“确认 Muse 与主聊天”，管理器提示：

> 操作未完成（HTTP 409），请查看本实例登录或绑定状态。

现场只读检查表明，Muse 网页已认证，主聊天的连接、历史和订阅均已就绪，四项必需认证 Cookie 均存在且未过期。失败发生在本机采集认证信息之后：Muse 新增的 `__Host-hatch_one_tap` Cookie 名称包含连字符，而 `OneAccount.inject()` 只接受字母、数字和下划线，因而拒绝整个 Cookie 集合。底层采集错误被管理器统一显示为 HTTP 409。

同时检查到恢复路径将所有 Cookie 的 Domain 设为 `.muse.ai`，不满足 `__Host-` 前缀 Cookie 禁止设置 Domain 的要求；仅修复名称校验仍可能使后续恢复或续期失败。

## 修复

- `real/common.py`：Cookie 名称校验允许连字符，接受 Muse 的前缀 Cookie；仍拒绝空名称、空格、分隔符和控制字符，仍要求四项必需认证 Cookie。
- `real/strict_engine.py`：恢复 `__Host-` Cookie 时使用 `https://muse.ai/` URL、`Path=/` 和 Secure，省略 Domain；普通 Cookie 保留原域配置。
- `real/test_account_cookies.py`：覆盖前缀 Cookie 的采集、续期和恢复，非法名称/值拒绝、必需认证项缺失，以及恢复时的主机作用域。
