# Muse 微信管理台 · 0.1.0-preview-r11

这是 Windows 本机管理软件，可直接使用或通过远程桌面访问。首期提供 6 个独立实例配置，可继续添加；每组的登录、端口、凭据和消息数据分别隔离。

r8 优化了 Muse 完成后的文字转发等待：明确完成的普通文字经过 400ms 一致性确认即可进入微信发送队列。图片、附件及完成状态不明的内容仍保留 3 秒确认。该窗口不包括 Muse 自身生成或微信网络耗时。

## r11 更新

修复 Muse 登录后确认主聊天报 HTTP 409：接受带连字符的前缀 Cookie，恢复时保留 `__Host-` 的主机作用域。所有实例共用修复后的程序。发布内容和旧目录升级说明见 [r11 发布说明](https://github.com/such99/muse-wechat-manager-public/blob/main/docs/RELEASE-r11.md)；已应用修复且运行正常的既有安装无需重装。

遇到提交结果不明，可在微信管理页选择对应入站项；核对 Muse 原输入后，确认已提交或取消旧项。Muse 管理页另有指定输入及生成暂停恢复入口。操作保留去重，不重新发送/生成。页面忙碌、草稿、账号变化或确认记录过期会拒绝，旧请求仍在途中时不能声称已取消。

未提交的排队文字和附件都只在内存；停止/重启后需要重发。程序会在原发送者下次入站时提示数量；明确未提交的同 ID 重投可以重新入队。详情与剩余限制见 docs/CLAUDE-REVIEW-FIXES.md。

## r10 更新

按原生类型跳过浏览器任务的运行/停止状态卡和空占位，保留普通文字、图片与文件。网页和提醒显示 `[网页]`、`[提醒/任务入口]` 等文字说明；截图转发尚未实现。任务卡附带文件时也不会误触发聊天生成失败。

程序不再按累计发送次数暂停。实际微信接口拒收仍会保留队列并等待新的微信消息；发送结果不明时需人工核查，不自动重发。首次连接或桥接重启后可能需要先从绑定微信发一条消息建立会话。

## 第一次使用

1. 将 ZIP 完整解压到当前 Windows 用户可写的目录。不要在压缩包内运行。
2. 双击 `Muse微信管理台.exe`，浏览器会打开 `http://127.0.0.1:18700`。
3. 从第一组开始，点击“启动”。需要本机安装 Google Chrome，默认查找 `C:\Program Files\Google\Chrome\Application\chrome.exe`；其他安装位置可在启动器运行前设置进程环境变量 `MUSE_CHROMIUM`。软件随包提供 Python 和所需库，不会自动安装或更新依赖。
4. 点击“登录 Muse”，在本实例专用隐身窗口完成本人登录。页面就绪后，点击“确认 Muse 与主聊天”。核对账号归属后确认。登录凭据使用 Windows DPAPI 加密保存到本机 `secrets/`。
5. 点击“扫码绑定微信”，阅读说明并生成真实二维码。二维码由现有 iLink Bot 通道提供；功能是扫码者与 Bot 对话，不接管普通微信全部好友和群聊。登录资格及授权范围以手机端实际提示为准。
6. 用该实例使用者自己的微信扫码，核对手机授权后点击“检查状态”。显示授权完成后，先给 Bot 发一条消息，再点击“确认扫码者绑定”。这条绑定消息不转发给 Muse。
7. 发送两轮中文消息，在手机核对实际回复后点击“确认真实收发”。图片、附件需另发真实样本核验。语音暂缓。
8. 第一组验收后，依次完成其他组。至少 6 组的真实登录和并行聊天需要各自账号；离线测试不能替代真实账号验收。

新建实例默认不记录正文日志；若原配置开启，则仍会记录。主聊天发送队列会在本机 SQLite 保存明文助手文本，DPAPI 只保护凭据。不要把自己的 `runtime/`、`secrets/`、`manager-data/` 或整个使用后的软件目录发给别人。

## MiMo 管理助手

点击“配置 API”，在服务器本机输入官方 Base URL、模型 ID 和 API Key。默认接口为 `https://api.xiaomimimo.com/v1`，模型 ID 可根据自己账户可用模型修改；Token Plan 请使用平台给出的专属官方 URL。密钥加密保存在服务器，界面不回显。

可输入“检查 member01 为什么连接不上微信”“重启 member02”等指令。MiMo 接收精确实例 ID、布尔运行状态与允许的事件统计；聊天正文、账号标识、原始错误、Cookie、Token 不进入诊断上下文。MiMo 生成的启停、重连、解绑、删除操作必须在本机点击明确目标后执行。模型输出和日志不能直接执行系统命令。

日常微信对话由本组 Muse 处理。MiMo 的密钥和对话不参与微信消息生成。

## 停止、重连与恢复

- “停止”只停止当前实例，并取消下次自动启动。
- “重连”会停止再启动当前实例，可能中断进行中的对话；不自动重发提交结果或送达情况不明的消息。
- “退出软件”会停止管理器自己启动的实例，保留下一次打开时的恢复意愿。
- 再次打开软件会自动启动此前运行的组，尝试恢复原 Muse 和微信授权。Muse 恢复会核对保存的原账号指纹；不匹配、Cookie 过期或登录验证失败时要求本人重新登录。微信授权失效时需要重新扫码。
- 恢复后的微信待发送消息可能需要该微信用户先发新消息建立可用回复上下文。遇到发送受限或状态不明，点击“主聊天与队列”核对队首项，不能盲目重发。微信授权失效后，请先“重连”本实例再扫码，防止旧轮询和新授权混用。
- DPAPI 加密凭据与当前 Windows 用户绑定。更换服务器或 Windows 用户时请重新登录；不能保证拷贝目录后恢复授权。
- “解绑”停止本组并清除本机微信绑定，保留 Muse 加密登录和消息记录。平台授权如需彻底撤销，请在手机微信端操作。
- “删除”清除本组配置与加密凭据，默认保留普通数据供人工备份或清理，不影响其他组。
- 服务器重启后需进入远程桌面并再次打开 EXE；本版没有注册 Windows 后台服务或开机计划任务。

首次验收请使用独立的 Muse/微信账号；不要把同一账号同时绑定到多个实例。

## 边界和交付状态

本包是可启动的集成预览版。请以 `TEST-REPORT.md` 及 `ACCEPTANCE.md` 的逐项矩阵为准：本地加密、进程及模拟消息验收与真实 Muse/微信/MiMo 验收分别记录。没有真实密钥或账号的测试不得显示为实际业务验收成功。

管理端口、Muse API、微信桥接和浏览器调试端口仅在回环地址使用；不修改其他软件、网络配置或防火墙。既有实例数据不会自动迁移进发布包。

## 源码、依赖与构建

`real/` 是应用源码，`packaging/Launcher.cs` 是启动器源码。手册与启动器只维护 `packaging/` 中的版本；便携包根目录另有构建生成的便捷副本。`manifest.json` 记录版本、文件哈希、Python 官方来源及哈希、上游 Git 地址和 SHA、第三方库版本。Python 许可位于 `licenses/`，第三方库的许可证随各自 `.dist-info` 目录保留，上游许可证在 `vendor/`。

浏览器使用服务器已经安装的 Google Chrome，未再分发浏览器。运行需要 Windows 的 .NET Framework 4.x（启动器）以及与 CPython 3.13 兼容的 Windows x64。

开发依赖锁是 `requirements-dev.lock.txt`；`packaging/upstream-lock.json` 固定所需上游源码的来源、提交及逐文件哈希，重建不依赖上游 `.git` 目录。请使用官方 CPython 3.13.14 Windows x64 完整开发环境，在软件源码根目录用 PowerShell 运行：

```powershell
python -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements-dev.lock.txt
New-Item -ItemType Directory -Path build-cache -Force
Invoke-WebRequest -Uri 'https://www.python.org/ftp/python/3.13.14/python-3.13.14-embed-amd64.zip' -OutFile 'build-cache\python-3.13.14-embed-amd64.zip'
& .\.venv\Scripts\python.exe -I packaging\build.py --output 'C:\MuseBuild\全新发布目录'
```

首次开发安装和下载需要联网；构建脚本校验 Python 包 SHA256，值见 `manifest.json`，并校验上游源码哈希。运行软件不需要联网下载组件。脚本只从明确文件清单和安装分发记录复制组件，拒绝覆盖既有目录，禁止复制运行中的私人数据。修改选定上游文件后，需人工审查并更新对应锁；不要绕过哈希校验。构建前不要把使用后的凭据或日志复制进源码交付包。

本机/模拟回归共 134 项，完整命令与 Node.js 要求见 `CONTRIBUTING.md`。测试仅使用假身份和本机进程，不向真实账号发送消息。

r9 的认证确认字段统一为 `confirm_owner`，正式微信绑定角色为 `owner`，临时测试角色保持独立。自行调用本机接口的客户端需使用新字段。

需要更换管理端口时，可通过 PowerShell 运行 `& '.\Muse微信管理台.exe' --port 19700`。便携包检查支持 `python -I packaging/verify_bundle.py <ZIP路径> <不存在的解压目录> --port 19700`；先选择空闲端口。脚本会修改临时解压副本的第一组测试端口并启动、重启、停止测试进程，不应对使用中的软件目录执行。

发布 ZIP、manifest 和便携包验证结果保存在 GitHub Releases；源码仓库 `distribution/` 仅保留 SHA256 校验值。不要从已登录的软件目录制作新发布包。
